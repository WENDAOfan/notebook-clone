# 枫岚东站状态题：证据范围诊断协议

原始 `dense-near-v1` 中，`dense-maplelan-east-status` 的本站工单在直接检索和 Agent 来源都排第 1，但答案把“截至 2026 年 3 月 31 日没有完成更换的交接记录”概括为“尚未完成”。前者是记录状态，后者断言实际状态；该题已按原预注册标准判失败。本诊断在看新的回答前固定，不修改原报告或 80 篇题集。

复用 `eval/context-ablation.js`：问题、生产 `handleAskStream`、提示词、DeepSeek 配置、空会话历史都不变，只有检索工具返回不同。`saved-full` 回放原两轮全部选中片段，`saved-top5` 各回放前五块，`gold-one` 仅回放原始融合候选中本站故障工单。三组各重复三次，全部结果保留，不挑选最好的一次。脚本先核对原轮次片段 ID 与来源顺序及生产作答/检索代码哈希；它不重新索引、不调用 Embedding，也不使用个人知识库。

事先固定判读：合格回答应明确“资料显示只提交申请，截至 2026 年 3 月 31 日没有完成更换的交接记录”，不能把缺少交接记录断言为实际一定未完成；不得用别站工单支持本站结论。记录每次的结论、引用是否对应该工单、额外邻站内容及响应耗时。若 `gold-one` 仍误断实际状态，优先检查作答的时态约束；若只在范围较宽时误断，继续检查证据噪声；两者都不能由三次重复推出稳定概率。

在 `notebook-electron` 目录中执行：

```powershell
node eval/context-ablation.js --case-id dense-maplelan-east-status --repeat 3
node eval/context-ablation.js --case-id dense-maplelan-east-status --repeat 3 --online --label status-v1
```

本实验属于看过失败后的诊断，不是独立留出验收；任何结果都不能改写原始 80 篇报告的未通过结论。

## 首次结果（2026-09-29）

九次均正常结束，引用编号均有效。按上面的严格时态标准，`saved-full` 为 0/3、`saved-top5` 为 0/3、`gold-one` 为 1/3。唯一通过的是金标准第 2 次，明确限定为“就已检索到的文档而言，未记录为已完成”；其他八次出现“尚未完成”“并未完成”等未限定的实际状态断言。来源数量分别约为 45、7、1，缩短证据仍不能消除该误断。部分宽证据回答还额外引用别站已完成的工单，虽注明不能套用，也没有帮助回答本站实际状态。

这只说明**此题的失败不全由无关来源造成**；三次重复不足以估计稳定概率，也不能证明提示词是唯一原因。原始九次回答保留在本地忽略的 `eval/context-ablation-status-v1-report.json`。下一步须先冻结全新的“无完成记录／明确未完成／明确已完成”对照题，再测试规则修改，不能拿这道已经看过的题继续充当留出验收。
