# 桌面 RAG：证据范围对回答的受控诊断

在第一次在线运行前固定：只复核 `dense-near-v1` 的
`dense-two-song-prices`，原始生产回答错误地把“两个站的采购单价”
答成了“另外两个站的保修月数”，即使松蓝西站 15.8 万元的证据在来源第 1 位。
原始报告 `eval/dense-near-all-baseline-v1-report.json` 和题集 SHA-256
`87a77119f548f81941488290d7bc201cd0b879f1d29c84b6225c2e8f8c593565`
不得修改。脚本在运行前核对已保存的两轮候选能**逐片段、逐顺序**重建原始
40 个来源，否则拒绝对照。

使用相同的生产 `handleAskStream`、系统提示词、工具循环、DeepSeek 配置、
同一个问题和空会话历史；仅将检索工具的返回替换为固定虚构证据：

| 组别 | 每轮证据 | 目的 |
| --- | --- | --- |
| `saved-full` | 原报告第 1/2 轮分别选中的 32/30 块，去重后 40 块 | 检查原始证据下错误是否重复出现 |
| `saved-top5` | 上述两轮各自前 5 块 | 只缩小已提供的证据，不新增遮盖单价材料 |
| `gold-two` | 原融合候选中两个指定站点的预算摘录，各轮重复返回 | 检查模型在正确且很短的证据下能否答对；这是**金标准上界** |

每组运行两次，共六次问答；顺序固定为每轮依次运行三组，报告全部保留，
不挑选“最好的一次”。正确答案必须同时说出“松蓝西站 15.8 万元”
和“松岚东站实际单价无法确认”，并由对应本站摘录支持；
不能把项目预算 24 万元当单价，也不能答成保修问题。
另记是否编造“资料不存在”、无效引用、检索次数、最终来源数和耗时。

默认仅离线准备；显式 `--online` 才调用**已有 DeepSeek 对话模型**。
不调用 Embedding，不重建索引，不访问个人知识库；用独立内存数据库，
结果写入被 Git 忽略的 `eval/context-ablation-<label>-report.json`。
每组两次不足以估计稳定概率，且固定证据回放绕过了真实生产检索，
所以无论结果如何，不能拿此实验改写 80 篇资料的验收分数或宣称已修复。

在 `notebook-electron` 目录运行：

```powershell
node test/context-ablation.test.js
node eval/context-ablation.js
node eval/context-ablation.js --online --label v1 --repeat 2
```

## 首次结果（2026-09-29）

六次均正常结束、引用编号均有效；生产作答/检索代码组合哈希与原始报告相同。
按上述完整标准，原保存全部来源 **0/2**、每轮前五块 **0/2**、
两份正确预算原文 **2/2**。前两组有回答说对主结论，但仍留下邻站错误
数值或缺少松岚东站对应预算证据，不能计作严格通过。
首次生产运行答成保修，此次即使用原保存 40 个来源也没有重复同一错误；
同时截到前五块的一次回答竟错称来源 [1] 的站点没有采购记录。
因此只能确认模型输出存在波动、证据完整性很重要，不能宣称“缩短上下文
即可修复”。逐次人工判读在本地 `eval/context-ablation-review.md`，
原始逐次回答在 `eval/context-ablation-v1-report.json`。
