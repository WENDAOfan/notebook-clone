# v1.1.5 - RAG 系统提示词分层重构：消除机械化拒答，支持连贯上下文多轮交互

## 1. 改进背景与问题诊断

在多轮问答对话中，用户提问：
> “你知道我之前有提什么问题吗”

大模型给出了极其死板的机械回答：
> “根据文档内容，无法找到相关答案。文档中未记录用户之前提出的问题。”

### 根因分析
在 [rag-service.js](file:///d:/JetBrains/notebookproject/notebook-electron/rag-service.js) 的原有设计中，系统提示词（System Prompt）对大模型施加了过于严苛的单一规则：
1. `只基于用户提供的【文档内容】回答问题`
2. `如果文档中没有相关信息，明确回答"根据文档内容，无法找到相关答案"`

尽管程序在组装 `messages` 请求体时完整包含了先前的对话历史（`historyMessages`），但大模型由于严格服从 System Prompt 的“**只看文档内容**”与“**文档无记载即拒答**”禁令，不敢调用会话上下文来回答有关“元对话”（如追问前文、总结上一轮、询问用户刚才说了什么等）的问题。模型被迫在文档切块中寻找“用户的问题”，找不到便机械触发拒答。

---

## 2. 提示词分层架构设计 (Hierarchical Prompt Architecture)

为了在 **“保持知识库事实严谨性（防幻觉）”** 与 **“保持多轮交互连贯自然”** 之间达到平衡，我们将原有的“一刀切”规则重构成“分层响应机制”：

### A. 规则分层说明
1. **事实知识层（严格防幻觉）**：
   * 凡涉及文档主题相关的客观知识、技术细节、数据、定义与方案时，模型必须严格依据【文档内容】回答，严禁凭空捏造；
   * 在陈述来自文档的事实时，必须在句末准确标注引用编号 `[N]`。
2. **上下文与交互层（自然连贯交互）**：
   * 凡涉及对对话历史的追问、回忆（例如“我刚才问了什么”、“你上一条回答的要点是什么”）、要求换种方式表达（如“用通俗的话解释上一句”）、或日常问候交流时；
   * 模型应结合对话上下文自然作答，无需受限于必须在【文档内容】中查找，也不需要打上 `[N]` 引用。
3. **未提及事实友好说明**：
   * 仅当用户明确询问专业知识点，且【文档内容】和会话上下文中确实未记载时，才明确且友好地说明文档中未找到相关答案。

## 3. 提示词重构对比

```diff
 你是一位知识库问答助手。请严格遵循以下规则：
-1. 只基于用户提供的【文档内容】回答问题
-2. 如果文档中没有相关信息，明确回答"根据文档内容，无法找到相关答案"
-3. 回答要简洁，控制在 300 字以内
-4. 不要添加文档中没有的信息
-5. 如果有多篇文档，综合各篇文档的信息进行回答
-6. 每段内容前面标注了 [N] 来源，引用事实时必须在对应句末添加 [N]
-7. 不要自行编造或输出参考来源列表，界面会根据 [N] 渲染来源
+1. 针对文档事实与专业知识的提问，必须严格基于提供的【文档内容】回答，不得编造无关事实；
+2. 若用户在针对对话历史进行追问、总结、回忆（如"我之前问了什么"、"总结你上一轮的回答"）或日常交互指令，请结合历史上下文自然作答，无需受限于文档内容；
+3. 仅当用户询问专业知识且【文档内容】中确实未提及、无法推导时，才明确回答"根据文档内容，无法找到相关答案"；
+4. 如果有多篇文档，综合各篇文档的信息进行回答；
+5. 每段文档内容前面标注了 [N] 来源，引用文档事实时必须在对应句末添加 [N]，回答非文档的交流/追问内容时无需标注；
+6. 回答要清晰简洁，控制在 300 字以内；
+7. 不要自行编造或输出参考来源列表，界面会根据 [N] 渲染来源。
```

## 4. 验证方式

1. 离线单元测试回归：`npm test` 保证全量 39 项单元测试全绿。
2. 真实多轮对话测试：
   * 提问“什么是 RAG” $\to$ 模型基于文档输出并带 `[N]`；
   * 接着追问“你知道我之前有提什么问题吗” $\to$ 模型正确识别前文并复述用户的提问，不再机械回复“文档未记录”。
