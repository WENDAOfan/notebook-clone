# v1.2.2 认证边界自动化测试设计

## 学习目标

用 `/api/auth/me` 的真实安全缺陷演示一次完整的测试驱动修复：先用自动化测试描述
安全规则并观察失败，再修改安全配置，最终让测试稳定通过。

## 测试类型

采用 Spring MVC 安全切片测试：只加载 `AuthController`、`SecurityConfig`、
`JwtAuthenticationFilter` 和 `JwtUtil`。`AuthService` 使用 Mock 替代，因此不会连接
PostgreSQL，也不会调用任何 AI API。

## 安全规则

1. `POST /api/auth/register` 和 `POST /api/auth/login` 允许匿名访问。
2. `GET /api/auth/me` 未携带 Token 时返回 HTTP 401。
3. `GET /api/auth/me` 携带有效 JWT 时返回 Token 中的用户名。
4. `GET /api/auth/me` 携带无效 JWT 时返回 HTTP 401。

## 修复方案

- SecurityFilterChain 只匿名放行注册和登录，不再放行整个 `/api/auth/**`。
- JWT 过滤器只跳过注册和登录，让 `/api/auth/me` 正常解析 Token。
- 统一未认证响应状态为 401，并返回 JSON 错误体。
- 删除会加载整套数据库和 AI 配置、但没有业务断言的旧 `contextLoads` 测试。

## 验证命令

```bash
./mvnw test
```

测试不依赖网络、数据库或真实 API Key。
