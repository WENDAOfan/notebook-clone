# Java 文档问答上下文策略

本轮只调整 Java 问答策略，不改变 Electron 和 HTTP/SSE 返回格式。

- 普通聊天（useDocumentContext=false）跳过文档状态检查和向量检索；保留已有对话历史。
- 复用 chunkCount：null/0 表示尚未就绪（不声称后台一定正在运行），负数表示索引失败，正数表示已建索引。空正文单独提示。
- 单文档和笔记本在资源归属校验后检查索引状态。笔记本内非空文档必须全部就绪，避免把部分资料的答案误当作完整比较；空正文不阻塞其他文档。
- 无命中时返回固定的无证据提示，不再回退到截断全文。暂不新增相似度阈值，阈值需要后续黄金用例校准。
- RagContextService 统一产生上下文或提示；四个同步/流式入口共用。状态提示在历史压缩、模型调用前返回，不保存为一轮模型回答。
- 不迁移数据库、不新增索引重试接口；未索引的手动文档明确提示尚未就绪，不假称稍后会自动完成。

验证：普通聊天不调用检索；未就绪/失败/空内容/无命中不调用模型；就绪证据用于生成；笔记本混合状态；同步和流式结果一致。全部离线测试，不使用付费模型。
