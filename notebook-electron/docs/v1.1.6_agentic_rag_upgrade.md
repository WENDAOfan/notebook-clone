# v1.1.6 - 常规问答升级为 Agentic RAG：实现自适应意图路由与多步自主检索

## 1. 背景与演进目标

在先前的版本中，桌面端存在两套问答体验：
1. **普通问答（问答面板默认模式）**：采用传统的单向管道式 RAG（用户提问 $\to$ 无条件执行一次混合检索 Top-K $\to$ 拼成 Context $\to$ 一次性让大模型生成）。
2. **整理 Agent（特定子模式）**：具备工具调用能力的 ReAct 智能体。

这种分离带来以下缺陷：
- **普通问答机械死板**：即使用户只是打招呼或追问历史（“你知道我之前问了什么吗”），系统依然会去强行执行一次混合检索，并容易因为上下文冲突给出机械拒答；
- **难以处理多跳与多文档对比**：如果用户提问涉及对比两篇文档或多角度分析，单次固定检索（Top 5）容易出现证据不均衡或漏检；
- **检索式僵化**：拿用户口语化的整段提问直接计算向量和 BM25，词句噪音大。

因此，我们在 `v1.1.6` 将常规问答全面升级为 **Agentic RAG（对话智能体驱动）**。

## 2. 架构设计与工具循环 (ReAct Loop)

```mermaid
flowchart TD
    User([用户在主对话框提问 + 历史对话]) --> Agent[DeepSeek 问答智能体]
    Agent --> Decision{自主判断意图}
    
    Decision -->|A. 闲聊 / 对话回忆 / 格式调整| StreamDirect[免检索直答<br/>零检索开销 · 秒级流式输出]
    Decision -->|B. 涉及文档事实 / 专业知识| CallTool[调用 search_knowledge_base 工具<br/>动态提炼搜索词]
    
    CallTool --> ExecTool[调用本地 Hybrid 向量+BM25 检索]
    ExecTool --> RetFeedback[向前端推送 chat:sources 来源卡片]
    RetFeedback --> EvalTool[反馈切块给 Agent]
    
    EvalTool --> NeedMore{证据足够吗？}
    NeedMore -->|是| StreamFinal[带 [N] 溯源精准流式回答]
    NeedMore -->|否/涉及复杂多文档对比| CallTool
```

### 核心设计细节：
1. **动态工具注册**：
   * 注册 `search_knowledge_base` 工具，参数 `{ query: string }`，底层统一复用 `retrievalService.retrieve({ scopeType, scopeId, query, tokenBudget: 8000 })`。
   * 当用户开启“基于文档回答”时激活该工具；当单文档模式下用户关闭该开关时，回退为纯通用对话。
2. **自主按需检索**：
   * 大模型根据问题自主决策：如果可以通过历史上下文直接回答，则**不调用检索工具**，直接秒级流式输出；
   * 如果需要事实支撑，大模型**自主提炼出最精准的专业检索词**调用工具。
3. **多步追溯与证据聚合**：
   * 支持最大 3 轮工具循环，大模型在处理跨文档对比时可自主发起两次不同关键词的检索。
   * 每次检索到的来源切块，自动去重聚合后通过 `chat:sources` 发送给前端渲染来源卡片。
4. **向下兼容与流式中断**：
   * 保持既有的 `chat:chunk`、`chat:sources`、`chat:token-usage`、`chat:end` 事件完全一致。
   * 全面支持 `AbortController`，用户点击“停止生成”时立刻中止网络传输与工具执行。

## 4. 验证方式

1. 全量离线测试回归：`npm test` 保证所有既有测试全绿。
2. 真实大模型在线测试：
   * 闲聊与历史追问（“我刚才提了什么”）：验证不调工具秒回；
   * 专业知识提问（“什么是 RAG”）：验证自动调用工具并打上 `[N]` 溯源。
