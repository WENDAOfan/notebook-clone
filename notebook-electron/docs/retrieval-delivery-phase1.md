# 桌面检索改进第一阶段快照（2026-10-03）

这是紧凑重排实施前的历史记录，保留当时失败和默认关闭的决定。当前实现及最终结果以 [retrieval-delivery.md](retrieval-delivery.md) 为准。

本轮只改善 Electron 检索和相关评测，不修改 Java、不重建个人知识库、不提交 Git。基础检索改进已经默认接入；模型重排因最后一组长文问答耗时增幅未达标，保持默认关闭，仅保留显式实验开关。历史失败保留在 [实验记录](retrieval-ranking-v2.md)，不以新成绩覆盖旧报告；检索改进交付不等于整体RAG质量已全部通过。

## 软件里改变了什么

| 原问题 | 现在的处理 | 关键代码 |
| --- | --- | --- |
| 相似名称的共有字、型号子串压过真正对象 | RRF 后加入完整主体短语、完整型号的软排序；不硬删省略型号的合同证据，保护纯语义候选 | `retrieval-ranking.js` |
| 相邻残句排在完整条款之前 | 单向重叠降序；只在同一有效文档的唯一精确原文位置补齐首尾句，单侧256字符、总新增128 token | `retrieval-context.js` |
| “不适用于 LT-4”仍因出现 LT-4 获得高词法分 | 可选实验对最多16个候选用现有对话模型判断主体、型号、否定及时间关系；排序有收益但耗时门槛未全过，默认不启用 | `retrieval-reranker.js` |
| 每次 Agent 搜索都重排会增加耗时 | 每题最多一次重排尝试，后续继续基础检索；8秒超时/非法结果退回基础排序，用户取消终止 | `rag-service.js` |
| 在线默认改变后可能漏计用量、影响其他工具 | 单独记重排供应商用量，未知不记为零；整理 Agent 明确不启用问答专用重排 | `rag-service.js`、`agent-service.js` |

向量、BM25、RRF 保留。只检索 ready 且内容哈希和模型一致的索引；补全不能越文档、不能空结果读全文。每次最多八块、笔记本每文档最多三块、整题证据累计8000 token（含包装）不变。问答模型最多四次请求，另有最多一次重排请求。最终引用与超时规则不变。

`retrieval-service.DEFAULT_POLICY.rerank` 为 false，桌面默认也关闭，不因已有DeepSeek密钥而增加重排费用。在现有配置中显式设置 `"retrieval": { "rerank": true }` 且DeepSeek就绪，重启后才运行实验；false或缺失都不启用。没有修改真实密钥配置。重启源码版即可使用基础检索改进，已有有效索引无需重建；旧安装包需重新构建才包含这些代码。

## 真实生产检索结果

以下为同一真实索引、同一查询向量的三臂对照。baseline 为原始 legacy，control 为当前无模型重排，candidate 为当前加重排。均走生产索引与 retrieve，使用既有 `embedding-3`、`deepseek-chat` 和隔离临时库。Recall@5 按必要证据计，MRR 为证据级平均倒数排名，不等于标准按题 MRR。

| 题集 | 必要证据数 | 原 Recall@5 → 当前默认 | 原证据 MRR → 当前默认 | 默认 → 可选重排 MRR |
| --- | ---: | --- | --- | --- |
| 80篇近名，12有答案题 | 18 | 14/18 → 18/18 | .7620 → .8519 | .8519 → .8519 |
| 83篇资料，9有答案题 | 12 | 7/12 → 12/12 | .5417 → .8333 | .8333 → .8750 |
| 40篇数量不均资料，9有答案题 | 13 | 12/13 → 13/13 | .7308 → .8077 | .8077 → .8462 |
| 旧长文63块，8有答案题 | 15 | 15/15 → 15/15 | .7167 → .7389 | .7389 → .7500 |
| 新长文116块，10有答案题 | 12 | 12/12 → 12/12 | .6806 → .8611 | .8611 → .9167 |

上述均是回归，前四份报告为 `eval/retrieval-{dense-near-all,retrieval-holdout-holdout,retrieval-confirm-holdout,long-all}-semantic-regression-v1-report.json`，最后一份为 `retrieval-long-ranking-holdout-semantic-final-v1-report.json`。无答案支持证据召回也没有下降；找到“未披露”原文不等于最终回答必然拒答，问答另测。新长文无重排从补全前 .7639 到补全后 .8611，是实际提供上下文改善，不冒充纯排序模型收益；报告另存原始块证据排名。

旧长文的原始证据级 .80 门槛仍记为未通过。穷举实际分块得到该套最高约 .7556，多项必要事实不能同时排第一；不把除以上限的归一化分冒充原分。标准按题 MRR 为1，15项证据全在前五。新长文另行测试，不能借旧集上限问题免除新集目标。

## 重排实验的收益与未通过门槛

`boundary-holdout` 首次失败后明确转为校准/回归，不能再称盲测。题目未改，哈希 `e7e9ac3d579dfb9d5c9d097deb5a67e6fdbe837bd58d1c6d83d9939300f14128`。固定预算后，使用提前冻结且未用于调参的 `semantic-confirm` 确认，哈希 `2d1e57f77311dbd60ff69984ab1ff8f9df6e3f68cdacee31e5c372c57b4573f3`。

| 检查 | 校准/回归 boundary | 首次独立确认 semantic-confirm |
| --- | --- | --- |
| 资料规模 | 8份、80块、12题 | 8份、59块、12题 |
| 无重排 → 重排证据 MRR | .6564 → .8718（+.2154） | .8077 → .8718（+.0641） |
| 有答案 Recall@5 | 13/13 → 13/13 | 13/13 → 13/13 |
| 无答案支持证据前五覆盖 | 1/2 → 2/2 | 1/2 → 2/2 |
| 完整问答 P95 | 3325 → 4243 ms（+27.6%） | 3423 → 4312 ms（+26.0%） |
| 助手逐题复核关键事实及引用支持 | 10/10 | 10/10 |
| 助手逐题复核拒答 | 2/2 | 2/2 |

以上两组校准收益超过 .05、召回和拒答未下降、问答P95增幅不超过30%，独立确认方向一致。但是最后追加的长文回归P95为3140 → 4444 ms（+41.5%），仍未满足性能门槛，所以最终不默认开启重排。不能只引用上表两组来宣称性能全部达标。两组问答均正常结束，无空回答、无未知引用编号、无跨临时笔记本来源，每题重排最多一次。P95只代表本机本轮小样本，不保证所有请求或供应商网络状态。

原始报告：`retrieval-boundary-holdout-holdout-semantic-trial-v1-report.json`、`retrieval-semantic-confirm-holdout-semantic-frozen-v1-report.json`；问答四份为 `boundary-holdout-holdout-budget[-control]-v1-report.json` 和 `semantic-confirm-holdout-semantic-{control,frozen}-v1-report.json`（均在 eval）。问答生产核心代码哈希相同：`00ab2e463e87b06f123494cbb95921e1c534fa46a05c56fdbabf9a457151678b`。启动接线不改变该核心哈希，单独执行 main 启动适配器测试。

每轮检索都重排的旧方案 P95 曾从3417到5038 ms，+47.4%，失败报告保留；不是直接接受其性能退化。原有长文单独重排试验仅提升 .0139，也保留未达记录。

### 当前默认（关闭重排）的结果与剩余问题

- `semantic-confirm` 的默认检索 Recall@5 13/13、证据MRR .8077，达到 .85/.80 的检索目标；逐题实际答案9/10有答案主结论正确、2/2拒答。`sc-near-pad` 虽引用了凝川75天的正确证据，却把另一个主体宁川45天视为冲突，最后错误拒答，必须记为失败。重排实验该题答对，但不能据此说默认也答对。
- `boundary-holdout` 回归默认 Recall@5 13/13、证据MRR .6564，排序目标未通过；10/10有答案主结论正确、2/2拒答。其中价格题未在前五拿到“价格未披露”的明确片段，虽最终拒答正确，仍保留检索缺口。
- 新长文 `long-ranking` 默认 Recall@5 12/12、证据MRR .8611，10/10有答案主结论正确、2/2拒答；P95 3140 ms。日期、温度、维修条件、先断电/双人确认、新旧审批、淋雨后专业检查、跨文档期限均核对所引原文。答案有不必要的近名提醒和宽泛的“其他文档没有记载”表述，不能把主事实通过说成每句话都完美。
- 三组默认问答均无空回答或请求错误、未知引用编号零、跨临时笔记本来源零；累计证据token最大分别为6106、5758、7391，未超8000。以上均为助手复核，不替代独立人工盲审，报告原始状态未改。

默认问答原始报告分别为 `semantic-confirm-holdout-semantic-control-v1-report.json`、`boundary-holdout-holdout-budget-control-v1-report.json`、`long-ranking-holdout-semantic-final-control-v1-report.json`。新长文加重排报告为 `long-ranking-holdout-semantic-final-v1-report.json`，主结论10/10、拒答2/2、排序 .9167；但耗时增幅未达标，保留失败结论。

## 复现及交付边界

在 notebook-electron 目录执行。省略 `--online` 只准备；不带 `--rerank` 与桌面默认一致，显式带该参数才运行模型重排实验。`--label` 使用新值，脚本拒绝覆盖旧报告。只发送虚构样本，临时 SQLite 在内存，向量文件在工作区 D 盘临时目录，退出时清理。个人库不会被重建。

```powershell
node --test --test-concurrency=1
node eval/retrieval-compare.js --suite semantic-confirm --split holdout --online --label confirm-repeat-v1
node eval/production-cases.js --suite semantic-confirm --split holdout --online --label confirm-repeat-v1
node eval/retrieval-ceiling.js long
```

确认集现在已被看过，再跑只能称回归。数据量仍小，且以虚构机构政策资料为主，不能据此声称全领域100%召回或RGB官方分数。检索改善不能消除模型日期计算和过度推断等历史回答问题；本轮不改变它们的未通过记录。只有主动开启实验才每题最多多一次现有DeepSeek请求并消耗额度；供应商未返回用量的调用标未知，回答用量仍为估算，合计明确不含Embedding，不能作为精确账单。

## 最终收尾检查

桌面 main 启动适配器已验证：配置加载 → 应用检索策略 → 初始化数据库 → 打开窗口；已配置、显式关闭和未配置三种分支均覆盖。此为真实入口配合隔离适配器测试，不声称手动操作了可见窗口。

全套离线160项：157通过、0失败、3个在线测试默认跳过，约26.6秒。最后将默认重排开关改为关闭后，只复跑受影响的 main启动和策略5项，全部通过；没有重新计成全套160项。`git diff --check`、main/agent语法检查通过。所有在线临时向量目录已自动清理，报告保留；个人库、真实配置和Java文件未改。

本轮检索改善已实现并有真实生产对照证据；不是“所有质量门槛全部通过”。未达项明确为 boundary 排序、默认 sc-near-pad 过度拒答、重排长文相对耗时，以及原旧长文证据指标门槛不可达问题；不删题、不降低门槛、不用重排实验成绩替换默认成绩。
