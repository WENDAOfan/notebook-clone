# v1.2.9 文档上传一致性与向量失败恢复测试设计

## 目标

验证 Spring 版文档上传流程在解析、数据库保存和异步向量化失败时不会留下不可控的
半成品数据，同时保留用户已经成功保存的原文。

## 一致性边界

文档原文是核心数据，AI 摘要和向量索引是可重新生成的派生数据。因此采用以下策略：

1. 文件解析失败：不保存文档，不启动摘要和向量任务。
2. 笔记本归属校验失败：不保存文档，不启动后台任务。
3. 数据库保存失败：不启动摘要和向量任务。
4. 数据库保存成功：返回文档，并为同一个文档 ID 启动摘要和向量任务。
5. 向量写入失败：保留数据库中的原文，将 `chunkCount` 记为 `-1` 表示索引失败，
   并按本次生成的块 ID 尝试清理可能已经部分写入的向量。
6. 无有效分块（`chunkCount <= 0`）时，删除流程不应构造非法的向量 ID 范围。

## 测试方式

- `DocumentUploadConsistencyIntegrationTests` 使用真实 JWT 安全链和 MockMvc 发送真实
  multipart 请求，Mock Repository/Service 验证上传接口的副作用边界。
- `DocumentChunkServiceTests` 直接测试分块服务，Mock VectorStore 和 Repository，验证成功、
  空内容、文档不存在及向量写入失败后的状态与补偿清理。
- 测试先在现有实现上运行以暴露失败，再修改生产代码并运行完整 Maven 测试套件。
